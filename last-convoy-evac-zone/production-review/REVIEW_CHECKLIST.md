# 외부 리뷰 기준 — LCEZ

## 증거에 따른 판정

- PASS: 지정한 SHA의 요청 범위가 검토 기준을 만족함. 출시 승인/자동 병합 권한이 아님.
- CHANGES_REQUESTED: 근거 있는 결함 또는 기준 미달. 파일/장면, 재현 조건, 영향과 필요한 수정 제시.
- NEEDS_EVIDENCE: 미실행·접근 불가·다른 소스 버전의 증거 등으로 판단 불가. 결함이 없다고 간주하지 않음.

코드와 실행 증거, 게임 품질 판정은 별도로 표시한다. 기능 오류가 없다고 목표 아트·조작감까지 통과시키지 않는다. 상위 P0/P1이 있으면 전체 결과는 CHANGES_REQUESTED이며, 미검증 항목도 별도로 남긴다.

## 우선순위

| 등급 | 의미 | 대응 |
|---|---|---|
| P0 | 데이터 손실·비밀정보 노출·복구 불가 위험 등 | 관련 작업과 배포 차단, 사용자에게 명확히 알림 |
| P1 | 기동/작전 진행 불가·구조 중복 집계·핵심 경로 실패 | 관련 기능 확장·병합 전 수정 및 회귀 시험 |
| P2 | 조작·시야·UI·성능·밸런스가 정한 품질 기준 미달 | 마일스톤 완료 전 해결, 일정과 검증 조건 명시 |
| P3 | 비차단 폴리싱·선택적 개선 | 범위 통제된 백로그로 관리 |

## 검수 항목

### 1. 기술·규칙

- 실제 source SHA와 빌드/테스트 SHA 일치, 미실행 항목 구분.
- 농성/옥상 방어는 현장 안전 조건을 검사하고, 이탈·탑승 중단의 이유가 표시되는가.
- 구조 인원은 발견·접촉·보호·탑승·이송·탈출·손실을 구분하며 중복 성공이나 음수가 없는가.
- 트럭 파괴와 탈출이 같은 시점에 발생해도 정의된 우선순위로 한 번만 처리되는가.
- 길막·교차로·회전·재경로·호위 이탈 시 차량이 건물을 관통하거나 이유 없이 멈추지 않는가.
- 보병이 실제 후방 경로를 따르며, 주둔/이탈·재투입 때 위치와 획득 인원이 깨지지 않는가.
- 지도와 보급창에서 전투 입력이 남거나 일시정지 중 임무 시간이 잘못 진행되지 않는가.
- 연속 처치와 헬기 이탈 중 발생한 보급 요청이 유실되거나 영구 대기하지 않는가.
- 변경 없는 거대 함수 재선언, 전체 원본 삭제, 테스트 완화 등으로 임시 통과시키지 않았는가.

### 2. 게임 품질

- 전차 주포가 군집에 실제 통로를 만들고, 기관총/보병/차량의 역할이 구분되는가.
- 위험한 대상과 탈출 경로가 읽히며 플레이어의 화력 배치/출발 시점에 따라 결과가 달라지는가.
- 무적 전차·요새가 구조 목표의 위험을 전부 무의미하게 만들지 않는가.
- 도심·시골·농장이 외형만 아니라 접근로·군집 방향·구조 방식에서 달라지는가.
- 목표·중단 원인·남은 탑승 인원·차량 HP·재투입 공백을 별도 설명 없이 파악할 수 있는가.
- 시연자에게만 가능한 조작이 아니라 사용자 실제 플레이 의견이 반영되었는가.

### 3. 아트·UI·음향

- 사용자 승인 대표 장면에 맞는 저채도 3D 픽셀풍, 차량 비율·그림자·픽셀 밀도 일관성.
- 기본 줌에서 전차/APC/지프/트럭/버스와 보병/민간인/좀비 구별 가능.
- 건물·연기·폭발이 구조 목표와 가까운 위협을 장시간 가리지 않음.
- 지면 깜빡임, 픽셀 경계 흔들림, 유닛 미끄러짐, 부적절한 건물 관통이 없음.
- 전장 스타일과 무관하게 UI 글자는 선명하고 지도/미니맵의 정보 공개가 일관됨.
- 주포 반동·탄착·잔해·통로 변화가 보이고, 경고·탑승 완료 등 중요 음향이 묻히지 않음.
- 생성된 이미지/컨셉아트와 실제 플레이 녹화를 구분. 원본 레퍼런스 에셋 무단 복제 금지.

### 4. 성능·출시

실제 하드웨어·배포 빌드·해상도·품질 설정과 같은 장면을 비교한다. 군집, 차량, 시체, 연기, UI를 포함한다. 평균뿐 아니라 프레임 스파이크·지속 메모리 증가와 장시간 반복 생성/제거를 점검한다. 목표 최소사양은 실측 전 미확정이다. 500/1,000/1,500 좀비는 비교 시험 단계이지 성능 보장이 아니다.

출시 후보는 저장·설정·키 변경·튜토리얼·언어·배포 기동·오류 보고·에셋 권리를 추가 확인하고 최종 사용자 승인을 받는다.

## 리뷰 절차와 중복 방지

1. 관련 PR/head SHA 및 체크포인트 증거만 먼저 읽는다. 변화 없으면 이전 결과를 다시 작성하지 않는다.
2. 검토 범위의 diff, 필수 주변 코드, 실행 로그와 실제 화면을 확인한다. PR의 완료 문구를 독립적인 증거로 취급하지 않는다.
3. 중요 결함 우선으로 한국어 리뷰를 남긴다. 재현하지 못한 추론은 '가능성/정적검토'로 표시한다. 없는 결함을 만들어 내지 않는다.
4. 리뷰 키는 `repository + PR/branch + source_sha + evidence_id`이다. 동일 SHA라도 새 실행 증거/실패 상태가 제출되면 후속 검수한다.
5. 리뷰어 자신의 댓글·상태 기록 변경과 운영문서만의 수정은 새 게임 구현으로 재처리하지 않는다.
6. 같은 GitHub 계정의 자기 PR일 수 있으므로 기본 게시 방식은 COMMENT이다. 정식 APPROVE, 병합, force push, 공개 릴리스는 이 루프에서 하지 않는다.
7. 리뷰 중 HEAD가 바뀌면 검토한 SHA를 명시하고 새로운 SHA는 미검증으로 남긴다.

## 역할과 책임

사용자는 제품 방향, 플레이 감각, 대표 아트, 비용 및 최종 출시를 승인합니다. ChatGPT는 제작 총괄이자 구현 세션과 분리된 외부 리뷰 역할입니다. 사용자가 요청한 작업 배정은 `GPT-6 High: 설계·기술 검수`, `GPT-5.6 Luna Extra High: 주 구현`입니다. 이 명칭은 **요청값**이며, 실행 환경에서 선택되었는지 확인하기 전에는 적용 완료로 보고하지 않습니다.

외부 리뷰는 별도 인간/별도 GitHub 계정의 승인을 뜻하지 않습니다. 연결 계정으로 남긴 리뷰는 제목에 `LCEZ EXTERNAL REVIEW`를 명시합니다. 정기 리뷰 예약은 구현 에이전트나 로컬 Unity 실행기를 자동 시작하지 않습니다.

## 체크포인트 시점

| 시점 | 구현 담당의 행동 |
|---|---|
| 작업 시작 | 작업 ID, 기준 커밋, 목표와 변경 범위를 기록하고 작업 브랜치/초안 PR을 준비합니다. |
| 검증 가능한 기능 단위 완료 또는 실제 작업 60분 경과 중 먼저 도래한 시점 | 범위 내 변경을 점검하고 테스트 상태를 기록한 뒤 체크포인트 커밋·푸시와 PR 진행 기록을 갱신합니다. |
| 플레이/아트/성능 마일스톤 | 같은 소스 버전의 실행 빌드, 로그, 실제 화면·영상, 측정 조건을 제출합니다. |
| 동일 실패 2회 또는 필요한 권한/환경 부재 | BLOCKED 체크포인트를 남깁니다. 같은 명령을 무한 반복하지 않습니다. |
| 작업 종료·중단·담당 변경 전 | 미완료 상태, 다음 행동, 복구 기준을 원격에서 확인 가능한 형태로 남깁니다. |

60분은 작업 중 진행 기록 간격입니다. 작업이 없으면 빈 커밋을 만들지 않습니다. 테스트가 실행 중이면 중단하지 않고 PR에 진행 상황만 기록합니다. 컴파일 실패 중에도 안전하게 보존할 수 있는 변경은 WIP로 남길 수 있으나 정상 빌드로 표시하지 않습니다.

체크포인트 푸시는 **승인된 저장소의 작업 브랜치에만** 수행합니다. 이것은 main 병합이나 공개 출시 승인이 아닙니다. 실행 담당이 이 규칙을 읽고 로컬 세션에 적용해야 실제 푸시가 발생합니다.

## 외부 리뷰 루프

`작업지시 → 설계 → 구현 → 테스트 → 체크포인트 푸시 → 외부 리뷰 → 수정·재검증 → 승인된 병합`

정기 확인의 초기 간격은 1시간입니다. 새 코드 SHA, READY/BLOCKED 전환, 새로운 테스트·플레이 증거가 있을 때만 리뷰하고 알립니다. 같은 결과를 반복해서 알리지 않습니다. 변경이 없는 저장소를 매번 전체 재분석하지 않습니다.

리뷰는 PR COMMENT와 필요 시 추적 이슈에 기록합니다. 자동 병합·배포·릴리스는 하지 않습니다. 접근 불가나 증거 부족은 통과가 아니라 NEEDS_EVIDENCE입니다. 구현자는 다음 작업 전 새 리뷰를 읽고, 수정한 항목을 해당 커밋과 함께 답변합니다.

## 장기 품질 목표

Windows 싱글플레이 출시, 저채도 3D 픽셀풍 군사 아트, 도심·시골·농장 독립 작전 맵을 목표로 합니다. 다음 검수 단계를 건너뛰지 않습니다.

- M0 환경: 기존 작업 복구 가능, 정확한 에디터/패키지 확인, 실행·빌드 증거.
- M1 전투: 전차 기동·마우스 주포·보병 후방 추종·군집과 건물 이동의 신뢰성.
- M2 구조: 농성지 → 쉘터 → 탑승 → 호송 → 탈출, 실패와 중복 집계 방지.
- M3 표현: 목표 아트, 전투 손맛, 구조 중심 HUD·지도, 실제 플레이 가독성.
- M4 콘텐츠: 공통 규칙 위에 도심·시골·농장별 다른 경로·이벤트·부대 선택.
- M5 베타: 저장·설정·튜토리얼·언어·반복 플레이·성능 검증.
- M6 출시 후보: 배포 빌드·권리·미해결 결함 확인 후 사용자 최종 승인.

출시일과 최저사양 성능은 아직 확정하지 않습니다. 문서 작성량이나 커밋 수를 게임 완성도로 계산하지 않습니다.

- `REVIEW_CHECKLIST.md`: 외부 검수 기준과 리뷰 양식.
- `review-target.json`: 현재 확인된 참조와 미등록 출시 저장소 상태.
- `STATUS.md`: 적용 여부와 다음 착수 조건.
